Run an environment, secrets, and OAuth configuration audit for the Dax Collective project.

Context:
This project has multiple brands:
- Dax Collective
- Dax the Traveler
- Time-Zone Travelers
- Ani-Dax
- God’s Vessel
- Dax Photos / Google Photos integration

Current Google Cloud project: Dax-Automation.
OAuth clients already exist:
- DAX_PHOTOS
- DAX_TECH
- TZ_TRAVEL
- ANI_DAX
- GODS_VESSEL
- DAX_TRAVELER
- Dax-Main

API keys already exist:
- Google Sheets API Key
- Dax Collective YouTube API Key
- Gemini API Key 1st
- Gemini API Key 2nd

Goal:
Fix and organize the environment variable structure without exposing secrets.

Rules:
- Do not print, expose, log, or hardcode real API keys, OAuth client secrets, refresh tokens, service account keys, or private keys.
- Do not create .env files containing real secret values.
- Do not commit secrets.
- Do not touch origin/main.
- Do not push or deploy.
- Do not delete files.
- Do not modify unrelated visual design files.
- Use Replit Secrets for real values only.
- If a secret is missing, list the secret name only, not the value.
- If old/leaked credential files exist, flag them but do not delete until approved.
- Do not attempt to use a service account for Google Photos. Google Photos must use OAuth.
- Prefer backend-only secrets for sensitive API calls.
- Frontend REACT_APP_* variables are public once built, so only use them for safe public config or tightly restricted browser API keys.

Tasks:
1. Inspect current env usage across:
   - dax-main/.env
   - dax-backend/.env
   - package.json files
   - dax-main/src/config/
   - dax-main/src/services/
   - dax-backend/server.js
   - dax-backend/routes/
   - .replit
   - any env.example files
   - any credential folders
2. Identify every environment variable referenced in code.
3. Separate variables into these groups:
   - frontend public REACT_APP_* variables
   - backend private variables
   - Google API keys
   - Google OAuth client IDs/secrets
   - Google Photos OAuth
   - YouTube Data API
   - Google Sheets API
   - Google Drive API
   - Firebase client config
   - Firebase Admin/server config
   - n8n
   - ElevenLabs
   - Gemini
   - OpenAI/other AI providers
   - social posting APIs
4. Create or update safe template files only:
   - dax-main/.env.example
   - dax-backend/.env.example
   - docs/ENVIRONMENT_SETUP.md
5. Do not put real values in those files. Use placeholders like:
   - REACT_APP_GOOGLE_API_KEY=YOUR_RESTRICTED_BROWSER_KEY
   - YOUTUBE_DATA_API_KEY=YOUR_BACKEND_ONLY_YOUTUBE_KEY
   - GOOGLE_PHOTOS_CLIENT_SECRET=SET_IN_REPLIT_SECRETS
6. Check whether the current code expects incorrect names like:
   - BACKEND_GOOGLE_API_KEY
   - REACT_APP_YOUTUBE_API_KEY
   - GOOGLE_SECRET_N8N_MAIN
   - YouTube_Date_API_Key
   - Gemini_API_Key_1
   - Gemini_API_Key_2
   Standardize naming without breaking code.
7. Recommend exact Replit Secret names to add.
8. Identify which Google Cloud API keys should exist and what API restrictions each should have.
9. Identify which OAuth clients should exist and how each should be configured.
10. For DAX_PHOTOS, verify the required callback path:
   - /auth/google/photos/callback
   and determine whether the backend currently has a Google Photos OAuth route.
11. If no Google Photos OAuth route exists, propose the smallest safe route plan but do not modify backend files until approved.
12. Run a safe build or preview check only after inspection/template updates.
13. Report warnings/errors before any push or deploy.
