---
name: Execution and ownership
description: Daniel's construction-focused workflow, business outcome, and portable GitHub delivery requirements.
---

The goal is a polished, credible, revenue-producing Dax Collective digital property. Replit is the construction tool, not the product. Think outside Replit; execute inside Replit. Do not repeat the completed baseline audit, plans, readiness assessments, or design brainstorming unless new implementation facts require it.

**Why:** Daniel wants implementation spending to produce measurable product improvements rather than prolonged planning.

**How to apply:** Before proposing work, evaluate whether it materially improves the finished website, requires Replit execution, can be batched with other implementation, and will exist in GitHub afterward. For an authorized work order, inspect only what is needed, implement the approved scope, verify, fix issues, report results, and commit/push when that delivery is authorized.

GitHub should become the permanent source of truth: the complete working app must be cloneable and runnable without Replit, preserve the agreed V1/V2/V3 versions, document assets/configuration, remain maintainable by other developers/tools, and support eventual deployment elsewhere without proprietary Replit-only dependencies.

**Why:** Daniel requires ownership and an exit from dependence on Replit.

**How to apply:** Include authorized GitHub delivery and portability verification in milestone completion. Daniel wants completed Phase 1A committed/pushed before spending on Phase 1B. This policy is not itself authorization to start Phase 1A, push current work, publish, or promote V3; follow the explicit work order.

GitHub is engineering truth; Figma is visual truth. Figma should work against the real structure and functionality, not replace working code. Phase 1A architecture and Figma visual development can proceed concurrently.

**Why:** Daniel wants advanced visual design grounded in the owned, working codebase without waiting for the whole website to be finished.

**How to apply:** Preserve production on its protected branch, develop isolated V3 on a dedicated branch, and deliver verified commit/push checkpoints at meaningful milestones: foundation, approved Gateway/Traveler, remaining worlds, production candidate, and tagged production release. Do not checkpoint every tiny edit or wait until all of V3 is finished to make its foundation durable.

Premium quality comes from art direction, typography, spacing, imagery, deliberate motion, responsive polish, performance, coherent storytelling, and reliable behavior—not expensive technology.

**Why:** Daniel seeks agency-quality perceived value without agency-scale spending.

**How to apply:** Prefer straightforward React/CSS/SVG/Framer Motion and existing tools. Preserve successful behavior and isolated versions; add heavier technology only for a clear approved benefit.
